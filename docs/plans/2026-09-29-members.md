# Members Implementation Plan

## Context
The next item in `docs/plans/2026-09-28-library-management-design.md` is **`feature/members`**: member records with CRUD, search and deactivation.

Deferred to the loans PR: `GET /api/members/{id}/loans` and the "has active loans" checks. Both need the `loan` table, which doesn't exist yet.

Outcome: authenticated librarians can add, view, edit, search and deactivate members via `/api/members`, following the same rules and style as books.

## Existing code to reuse
- `exception/NotFoundException` gives 404. `BusinessRuleException(code, msg)` gives 409. `GlobalExceptionHandler` already maps unique-key violations to `DUPLICATE`, `ObjectOptimisticLockingFailureException` to `CONCURRENT_UPDATE`, and bad `sort` values to 400.
- `dto/PageResponse.from(Page)`. `max-page-size: 100` is already set in `application.yml`.
- `config/TimeConfig` provides the `Clock` bean, which sets `joinedAt`.
- Patterns to copy one-for-one:
  - `BookSpecifications`: blank input gives `unrestricted()`, plus `escapeLike`
  - `BookService.update`: stale-version check, then `saveAndFlush`
  - `BookRequest.OnUpdate`: validation group for `version`
  - `BookController`: 201 + `Location`, `@Validated({Default, OnUpdate})` on PUT
- Test patterns: `BookControllerTest` (`@WebMvcTest`), `BookRepositoryTest` (`@DataJpaTest`), `BookServiceTest` (Mockito), `BookApiIntegrationTest` (login as `admin`/`admin123`), `BookDuplicateRaceIntegrationTest`.

## Changes

### 1. Schema: `db/migration/V3__create_member.sql`
```sql
CREATE SEQUENCE member_code_seq START WITH 1;
CREATE TABLE member (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  member_code VARCHAR(10) NOT NULL UNIQUE,
  full_name VARCHAR(150) NOT NULL,
  email VARCHAR(254) NOT NULL UNIQUE,
  phone VARCHAR(30),
  active BOOLEAN NOT NULL DEFAULT TRUE,
  joined_at TIMESTAMP WITH TIME ZONE NOT NULL,
  version BIGINT NOT NULL DEFAULT 0
);
```

### 2. Entity: `entity/Member.java`
Uses `@Getter`, a protected no-arg constructor and `@Version Long version`.
- `Member(memberCode, fullName, email, phone, Instant joinedAt)` creates the member with `active = true`.
- `updateDetails(fullName, email, phone)`
- `deactivate()` is idempotent. Deactivating an already-inactive member is a no-op, so repeating the call is safe.
- `static normaliseEmail(String)` trims and lowercases the address. Stored emails are always normalised, so the unique index is case-insensitive in practice.

### 3. Repository
- `repository/MemberRepository`: `JpaRepository<Member, Long>` and `JpaSpecificationExecutor<Member>`. It adds `existsByEmail` and `existsByEmailAndIdNot`, plus `@Query(value = "SELECT nextval('member_code_seq')", nativeQuery = true) long nextMemberCodeNumber()`. That native query works on PostgreSQL and on H2 in PostgreSQL mode.
- `repository/MemberSpecifications`:
  - `matchesQuery(q)`: full name or email contains `q` (ignoring case), or the member code equals `q` (case-insensitive).
  - `hasActive(Boolean)`: `null` means no filter. `true` or `false` filters on that value, so `false` lists only inactive members. This differs from books' `available`, because "inactive only" is a real use case.

### 4. DTOs
- `MemberRequest(@NotBlank @Size(max=150) fullName, @NotBlank @Email @Size(max=254) email, @Size(max=30) @Pattern(digits, spaces, + - ( )) phone, @NotNull(groups = OnUpdate.class) Long version)` with a nested `OnUpdate` interface.
- `MemberResponse(id, memberCode, fullName, email, phone, active, joinedAt, version)` plus `static from(Member)`.

### 5. Service: `service/MemberService.java`
Class-level `@Transactional(readOnly = true)`, and `@Transactional` on writes.
- `search(q, active, pageable)`, `get(id)` (404 message: `"Member {id} not found"`)
- `create(req)`: normalise the email. A duplicate email gives 409 `DUPLICATE`. The code comes from `"M%04d".formatted(repository.nextMemberCodeNumber())`, and `joinedAt` from `Instant.now(clock)`.
- `update(id, req)`: a stale version gives `CONCURRENT_UPDATE`. An email already used by another member gives `DUPLICATE`. Then `saveAndFlush`.
- `deactivate(id)`: returns a `MemberResponse`. Loans will add a check here later if one is needed. The design doesn't block deactivating a member with loans, since they can still return books.

### 6. Controller: `controller/MemberController.java`
Routes under `/api/members`:
- `GET` takes `q` and `active`, with `@PageableDefault(size = 20, sort = "fullName")`
- `GET /{id}`
- `POST` returns 201 + `Location`
- `PUT /{id}` validates the `OnUpdate` group
- `PATCH /{id}/deactivate` returns 200 with the member

### 7. Docs
`docs/plans/2026-09-28-library-management-design.md` Members section:
- Document the request and response shapes, including `version` on PUT.
- Document the `active` tri-state and the code format.
- Note that the member-loans endpoint arrives with the loans PR.
