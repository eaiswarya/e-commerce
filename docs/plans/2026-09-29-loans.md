# Loans Implementation Plan

## Context
Members (PR #6) is merged. Next in `docs/plans/2026-09-28-library-management-design.md` is **`feature/loans`**: borrow, return and list loans, with the loan rules enforced. This PR also adds the member-loans endpoint deferred from Members, and makes book deletion safe once books have loan history.

Decision (agreed): deleting a book that has **any** loans, including only returned ones, is refused with 409 `HAS_LOAN_HISTORY`, so history is kept. To take such a book out of circulation, set `totalCopies` to 0. Books that were never borrowed can still be deleted.

## Existing code to reuse
- `Book.getCopiesOnLoan()` / `hasCopiesOnLoan()` and the `@Version` on `book` and `member`
- `LibraryProperties.loan()` (`periodDays`, `maxActive`): never hard-code 14 or 5
- The `Clock` bean (`TimeConfig`): "today" is `LocalDate.now(clock)`
- `BusinessRuleException` → 409, `NotFoundException` → 404, `ObjectOptimisticLockingFailureException` → 409 `CONCURRENT_UPDATE`, `MethodArgumentTypeMismatchException` → 400 `BAD_REQUEST`
- `PageResponse.from(Page)`. Test patterns are the same as books and members.

## Changes

### 1. Schema: `V4__create_loan.sql`
`loan(id identity PK, book_id BIGINT NOT NULL → book, member_id BIGINT NOT NULL → member, borrowed_at TIMESTAMP WITH TIME ZONE NOT NULL, due_date DATE NOT NULL, returned_at TIMESTAMP WITH TIME ZONE, version BIGINT NOT NULL DEFAULT 0)`, with indexes on `book_id`, `member_id` and `due_date`.

### 2. Entities
- `Book.borrowCopy()`: `availableCopies == 0` → `NO_COPIES_AVAILABLE`, otherwise decrement. `Book.returnCopy()`: increment.
- `Loan`:
  - lazy `@ManyToOne` `book` and `member`; `borrowedAt`, `dueDate`, `returnedAt`, `@Version`
  - `Loan(book, member, borrowedAt, dueDate)`
  - `markReturned(Instant)`: already returned → `ALREADY_RETURNED`
  - `isActive()`, `isOverdue(LocalDate today)`: active and `dueDate < today`. A loan due today is not overdue.

### 3. Repository: `LoanRepository` + `LoanSpecifications`
- `JpaSpecificationExecutor`, with `findAll(spec, pageable)` overridden with `@EntityGraph({"book","member"})` to avoid N+1
- `countByMemberIdAndReturnedAtIsNull`, `existsByMemberIdAndReturnedAtIsNullAndDueDateBefore(today)`, `existsByBookId`
- Specs: `hasStatus(LoanStatus, today)`, `forMember(id)`, `forBook(id)`; `null` → `unrestricted()`
- `MemberRepository.findWithLockById` (`PESSIMISTIC_WRITE`): serialises one member's borrows, so two borrows at once can't exceed the limit. The book's `@Version` stops two borrows taking the last copy (the second gets `CONCURRENT_UPDATE`).

### 4. DTOs
- `LoanStatus` enum `ACTIVE, OVERDUE, RETURNED, ALL`. `config/LoanStatusConverter` makes `?status=` case-insensitive, and an unknown value gives 400.
- `BorrowRequest(@NotNull @Positive Long bookId, @NotNull @Positive Long memberId)`
- `LoanResponse(id, bookId, bookTitle, bookIsbn, memberId, memberCode, memberName, borrowedAt, dueDate, returnedAt, status)`, where `status` is `ACTIVE`, `OVERDUE` or `RETURNED` as of today. It's built by `from(Loan, LocalDate today)`.

### 5. Service: `LoanService`
- `borrow(req)`, in one transaction:
  1. lock the member (404 if missing)
  2. find the book (404)
  3. inactive member → `MEMBER_INACTIVE`
  4. overdue loan → `MEMBER_HAS_OVERDUE`
  5. active loans ≥ `maxActive` → `LOAN_LIMIT_REACHED`
  6. `book.borrowCopy()`, then save the loan with `dueDate = today + periodDays`
- `returnLoan(id)`: 404 if missing; `markReturned(now)` (a second return → `ALREADY_RETURNED`); `book.returnCopy()`
- `get(id)`, `search(status, memberId, bookId, pageable)`, `memberLoans(memberId, status, pageable)` (404 for an unknown member; default `ALL`)
- `BookService.delete`: copies on loan → `HAS_ACTIVE_LOANS` (unchanged); otherwise `loanRepository.existsByBookId` → `HAS_LOAN_HISTORY`

### 6. Controllers
- `LoanController` `/api/loans`:
  - `GET ?status=&memberId=&bookId=`, default sort `borrowedAt,desc`
  - `GET /{id}`
  - `POST` (201 + `Location`)
  - `POST /{id}/return` (200)
- `MemberController`: `GET /{id}/loans?status=`, default sort `borrowedAt,desc`

### 7. Docs
Update the design doc's Loans and Members sections and the errors table with `HAS_LOAN_HISTORY`.
